# 灰度发布台（grayroll）

**所属领域：应用开发 · 子方向：全栈开发**

全栈产品：功能开关登记 → 环境绑定 → 人群圈选 → 灰度规则 → 发布生效 → 紧急熔断 → 单点覆盖 → 变更历史 → 在线求值。

## 骨架一句话

功能开关按环境配置灰度比例与人群，发布须版本落库才能生效，紧急熔断与变更历史同源。

## H3 切口候选（写路径互斥 · 须择一）

1. **发布生效**：同事务写入正式生效配置并升版本锁旧版，或只写影子发布草案、升正时原子落正式区（正式区升正前零改）。
2. **紧急熔断**：同事务立即写正式关闭并记变更，或影子紧急草案确认后原子熔断。
3. **人群绑定**：同事务写正式人群规则，或影子绑定草案升正。

正确性口径只能走甲乙中的一种且两边不得混用。

## 单点覆盖 · 强制开失效时刻（grayroll-03 拍板）

覆盖强制开**走乙路径**，不采甲路径。理由：强制开是「个案临时放量」，天然有生命周期；
若不与失效时刻同事务落库，求值侧会永久命中、历史侧则无到期痕可追溯。

**写入说明（当班封死）：**

- 缺失效时刻的强制开 → 只写影子覆盖草案 `override_shadows`，正式覆盖册 `overrides` 零增；接口返回 `mode=shadow` 与 `requires_expiry=true`。
- 显式携带失效时刻 → 同事务写正式覆盖行，并把到期时刻同时写入 `change_history.expires_at` 与详情文案。
- 影子升正同样必须带失效时刻；缺时刻的升正请求一律 400，正式册零改。
- 同一 `(flag, env, subject)` 的覆盖写口以同主体覆盖锁串行化；败方只写 `contention_marks` 争用痕，正式/影子账均零增。
- 求值侧：正式覆盖过期或缺失效时刻一律不命中；未升正的影子覆盖只提示 `pending_override_shadow`，绝不当作已强制开。

**取舍（不采甲路径，封死第三路）：** 甲路径（缺时刻也写正式行再补时刻）会让正式册出现无到期痕迹的行，
使历史页与求值页的口径分叉；因此取乙，并把「缺时刻」收紧为「只能进影子」。旧账中缺失效时刻的正式强制开
在求值侧回落正式规则并标 `override_missing_expiry`，不做数据改写。
